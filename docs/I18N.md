# Languages (i18n)

English is the default. A learner can switch to **Kannada (ಕನ್ನಡ)** from the header or from Settings; the choice is remembered in the browser (`settings.language`) and never leaves the device.

## What is translated (Phase 1)

| Translated | Not translated |
| --- | --- |
| Menus, headings, buttons, messages, Settings, the Why / About / landing pages, the panchang card (including city names, ordinals, weekday glosses, dates and times) | **Lesson content.** Lessons stay in English; each lesson page says so in the learner's language and tags the text `lang="en"` |
| The "unlocks on …" text, in the learner's date format | Sanskrit terms (shown in the learner's chosen script, as before) |
| | Draft-only lesson widgets in `drafts/` (not published) |

## Status: Kannada is a DRAFT

`kn.ts` has not been reviewed by a native speaker. While `reviewed: false` in `src/i18n/langs.ts`, the footer shows a "draft translation" notice in that language. To sign it off: have a reviewer read it (checklist in [CONTENT-REVIEW.md](CONTENT-REVIEW.md)), then set `reviewed: true`. A test pins the current state, so update it in the same commit.

## How it works

- `src/i18n/en.ts` is the source of truth: stable IDs → English text. `Key` is its type.
- `src/i18n/kn.ts` is typed `Record<Key, string>`, so **a missing key is a compile error**.
- `t(key, params)` returns text for the current language; `{name}` placeholders are filled from `params`. `dyn(prefix, id)` builds a key at run time (ordinals, weekdays, cities, landing lists).
- `<Msg k="…" />` renders messages with a tiny safe markup: `**bold**`, `*italic*`, `^^देवनागरी^^`, `[label](#/route)` or `[label](https://…)`. It produces text nodes, never HTML, so a translation cannot inject script.
- `App.svelte` wraps the page in `{#key app.language}` so everything recomputes on a switch, and sets `<html lang>`.
- Kannada gets its own font stack and line-height in `app.css` (`:lang(kn)`).

## Adding a language

1. Add the code to `LANG_CODES` and an entry in `LANGUAGES` (`src/i18n/langs.ts`): native name, English name, `locale`, `timeLocale`, `reviewed: false`.
2. Copy `kn.ts` to `<code>.ts` and translate every value; register it in `catalogs` (`src/i18n/index.ts`).
3. Add the font stack for `:lang(<code>)` in `app.css` if the script needs one.
4. Run `npm test`. The parity tests check, for every key: same placeholders, same links, balanced markup, non-empty, and actually in the target script.

## Translator guide

- Keep every `{placeholder}` exactly as written; move it where the grammar needs it.
- Keep `**`, `^^`, and link targets; translate only the visible words of a link.
- Sanskrit words in `^^…^^` stay in Devanāgarī.
- Don't translate the brand name "Dine Dine".

## Limitations / next steps

- Lessons are English-only. Translating them means a per-lesson `lang` field and a review pass per lesson; decide the first language before starting.
- Kannada numerals are not used (Western digits everywhere), as is usual in Kannada UI.
- Sanskrit in Kannada script is not offered yet.
